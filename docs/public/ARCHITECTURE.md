# 公开架构说明

## 研究与审查

`deep_researcher.py` 编排研究流程：建立研究目标、分配研究任务、使用搜索工具收集材料、压缩研究结果并生成报告。`reviewer.py` 提供独立审查，程序负责验证审查输出与允许的动作。

CLI 日常模式在报告后审查一次，必要时修改一次。保留的多阶段模式可在研究与交付阶段进行额外审查；两种模式的状态含义不同。单次审查的 `reviewed` / `revised` 不等同于多阶段模式的严格验收通过。

## 上下文与证据

`context.py` 和 `context_policy/` 为不同角色组装模型上下文。`artifacts.py` 保存原始证据、提取材料、模型请求、报告及用量；严格流程中的引用与修订还会经过程序校验。`recovery.py` 支持有边界的恢复与复核流程。

这些机制能检查结构和证据绑定，不能独立证明自然语言判断正确。真实搜索与模型行为可能产生无法收敛的审查，结果应保留其不完整状态。

## 配置和预算

`run.py` 负责运行身份、配置快照和图选择。`configuration.py` 解析模型、搜索、上下文及审查设置。

CLI 通过 `preflight.py` 检查显式付费开关、金额上限、模型价格与能力声明、所需密钥是否存在。`pricing.py` 默认读取包内 `default_pricing.json`；`ODR_PRICING_PATH` 或显式配置可指定其他价格表。包内表是有日期的估算快照，不能作为实时价格或供应商账单。

运行中的模型调用使用调用次数和 token 预算。模型费用估算与搜索费用分开处理。CLI 的预检查不能据此推定为所有 API 调用方式都提供相同的金额保障。

## 本地记录和发布范围

`observability.py` 支持关闭观测、本地观测和可选 LangSmith 导出。观测开关与研究证据归档分别控制；关闭观测不等于删除运行材料。

公开版本保留核心运行源码和必要配置。测试、评测语料、实验与验收档案、模型请求、日志、报告和个人笔记不随此快照发布。它们仍可能存在于开发者本地目录；请勿通过强制添加忽略文件的方式上传。
