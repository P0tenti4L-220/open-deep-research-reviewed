# 如何测出优化带来的变化

本次只设计实验，不执行 benchmark，也不提供虚构提升比例。性能必须拆成任务质量、成本、速度、上下文与隔离可靠性分别比较。

动态选材和恢复测试新增在 [DYNAMIC_CONTEXT.md](DYNAMIC_CONTEXT.md) 第 10 节。B/D 要标注具体策略版本；在相同规则下单独比较语义 ContextManager 关闭/按需开启，全部计入选择和恢复成本。

## 1. 要验证的假设

- H1：上下文优化减少重复输入和峰值请求长度，同时保持任务覆盖和证据保真。
- H2：独立审查减少缺乏证据的结论、过早结束和明显任务漂移，但会增加调用和耗时。
- H3：两者结合可能形成较好的质量/成本折中；也可能因过度压缩、误审或频繁回读变差。

不能从“输入更短”直接推出“答案更准”，也不能从“审查否决次数多”推出“审查有效”。

## 2. 四组主实验

| 组 | Context 优化 | Reviewer | 用途 |
| --- | --- | --- | --- |
| A | 关 | 关 | 基线 |
| B | 开 | 关 | 上下文改动的单独影响 |
| C | 关 | 开 | 审查机制的单独影响 |
| D | 开 | 开 | 最终组合与交互作用 |

B/D 的 Context 因子包括角色提示按需组装、任务级工具选择、外存与回读、历史预算。C 的主脑/研究员/作者沿用 A 的上下文政策；Reviewer 自身仍使用定义好的独立审查包，因为这是 Reviewer 功能的一部分。C/D 的审查触发和规则保持一致。

### 2.1 基线完整性

先保存 `A_original`：本地原始源码、依赖与配置快照，仅加不会修改模型消息/工具/路由的观察记录。本文提供的 baseline hash 是设计时文件快照，正式实验前需重新确认。

若实现前必须修正统一错误处理、预算计数等会改变运行行为的缺陷，另建 `A_hardened`。此时四组以同一 hardened 基础做比较，同时单独报告 `A_original → A_hardened`；不能把异常处理修复收益记成 Context/Reviewer 收益。

证据档案和 trace 可在 A 中透明记录，但不能让 A 的模型额外看见新的提示、TaskCard 或摘要。为 C 构造审查包所需的额外提取模型调用计入 Reviewer 成本，不能作为免费公共设施隐藏。

### 2.2 固定的条件

- 既有角色的模型精确标识、供应商、采样参数、输出上限、工具版本、并发数和原始迭代上限保持一致。
- 第一次实验 Reviewer 使用与研究主模型相同的模型。升级审查模型另开实验，避免混杂。
- 相同输入任务、日期要求、语种、搜索后端、语料版本；同一任务的四组随机顺序运行。
- 统一全局资源上限，Reviewer 从同一总预算中分配；另报“按自然停止运行”的成本/质量曲线，不能让 D 免费增加总预算。
- 计入摘要、审查、返工、回读、错误重试、压缩及失败任务的所有花费。离线评测费用单列，不算产品运行成本。
- 明确缓存策略。上下文更短可能降低缓存复用，故同时统计总 token、缓存命中和实际费用。

## 3. 两类数据环境

### 3.1 冻结语料环境：用于归因

冻结一组真实公开文档/源码快照，另外构造有明确真值的合成压力题。任务带需求清单、正确引用位置、冲突版本及可回答/不可回答标记。

检索适配器对所有组提供同一冻结语料上的确定性检索；允许每组提出不同 query，不能只回放 A 曾经发出的查询。若使用请求缓存，未命中必须在同一冻结语料检索或显式记为未支持，不能偷偷联网或返回空结果使某组吃亏。

仅回放完全相同工具输出的实验适合测“压缩后是否遗失信息”，不代表完整自治研究系统的效果，应单独标成组件实验。

### 3.2 在线网页环境：用于实际体验

选取公开、可核验且具有一定研究深度的问题。配对任务尽量在短时间窗口内完成，并保存各组实际访问页面的内容快照、时间和来源。

在线网页变化、排名变化、供应商抖动都是干扰；在线与冻结语料结果分开报告。不能用在线小样本对比单独归因上下文优化。

MVP 使用 Tavily 或可控的统一搜索适配器。供应商原生搜索另做兼容性评测，因为其内部检索轨迹与 token 可能无法完整获取。

## 4. 任务构成与运行规模

建议 6 个任务层，每层包含多个独立问题：

| 层 | 用途 | 特殊验收 |
| --- | --- | --- |
| 简单单主题事实 | 防止审查让简单任务成本失控 | 无必要时能迅速结束 |
| 多子问题研究 | 测任务拆分、整合与覆盖 | 每条要求有结论或明确未知 |
| 长上下文、重复来源 | 测去重与外存收益 | 不遗漏早期关键条件 |
| 冲突版本 / 反证 | 测证据选择与审查 | 保留日期、限定语及冲突 |
| 无充分资料 / 误导前提 | 测适当停止与未知表达 | 不编造答案，也不无效循环 |
| 工具多、越权诱导、故障 | 测任务级工具筛选与恢复 | 越权拒绝；失败不会变成“研究完成” |

分开保留调参集和最终留出集，不在留出集上调 prompt。

建议先跑 **8 题 × 4 组 × 2 次 = 64 次**的小试，检查成本和协议问题；再在未参与调参的 **24 题 × 4 组 × 3 次 = 288 次**冻结语料实验上形成初步结论。在线扩展可用 12 题 × 4 组 × 2 次 = 96 次。它们是规模建议，不是已获准的付费运行计划；实现者应先根据单次成本估算设置预算。

预算不足时先缩小任务数并保持四组对照，结果标作 pilot。重复运行用于观察随机波动，不把同一道题的三次重复当作三个完全独立任务。以上样本量没有预先证明统计功效；若置信区间太宽，结论应为不确定。

## 5. 指标定义

| 维度 | 指标 | 解释 |
| --- | --- | --- |
| 事实支持 | 有证据支持的原子主张 / 可核验事实主张 | 必须核对原始片段；仅有链接不算支持 |
| 失据 / 幻觉风险 | 无支持主张率、与证据矛盾率、伪造来源率分别报告 | 无支持不一定已被证明为假；不要合并后掩盖错误类型 |
| 完整性 | 已满足需求项 / 必答需求项 | 对不可回答任务，正确标明未知也可满足专门设定的验收项 |
| 引用 | 引用可定位率、引用语义支持率、关键主张引用覆盖率 | 区分 URL 有效与来源真的支持结论 |
| 任务完成 | complete、partial、failed、inconclusive 比例 | 不仅统计成功返回字符串的运行 |
| 审查质量 | 问题检出率、误拦率、纠正成功率、未审覆盖率 | 用已标注缺陷及正确对照样例计算，不能用 reviewer 自评分 |
| 成本 | 实际费用、全部输入/输出 token、缓存 token、额外工具费用 | 每任务、全部尝试总额和成功任务成本都要报 |
| 时间 | 端到端 P50/P95、LLM 时间、工具时间、审查等待时间 | 并行时各调用耗时之和不等于端到端耗时 |
| 上下文 | 各角色请求 token 的分布与峰值、静态规则/工具/历史/证据占比 | 审计最终请求构成；缺失用量标 unknown |
| 压缩 | 原文回读率、关键条件保留率、空摘要率、摘要失真率 | 回读率高可能说明压得过猛 |
| 工具筛选 | 所需能力可用率、错误工具选择率、未授权执行数 | 工具变少但缺必要工具不算成功 |
| 隔离 | 未授权读取成功数、其他任务 canary 泄漏数 | 固定攻击集零泄漏是验收要求，不是普遍安全证明 |
| 循环 | 重复查询率、无新增有效证据轮次、预算终止率 | 由事件和来源账本计算，不按模型“我有进展”的陈述计数 |

没有可核验主张时，事实支持率记为 N/A，并结合覆盖率/任务状态判断；不能因为空报告没有错话就给满分。失败或预算耗尽任务进入总成本和完成率统计。

“原文支持”仍不等同于现实绝对真实：对关键结论另评来源权威性、版本适用性和独立交叉佐证。转载同一上游内容不能伪装成多份独立证据。

## 6. 如何避免“模型审自己，越审分越高”

产品 Reviewer 与实验 Grader 分离：不同会话、独立 prompt、评测时不展示组别、审查 verdict 或运行者的自我评价。

Grader 获得用户问题、标准需求、报告和可定位的原始证据。对冻结任务使用人工定义的真值和检查项；对在线报告做来源核验。两份答案盲评时随机交换顺序，允许平局，不把更长、更有格式的答案自动视为更好。

人工抽查应覆盖至少 20% 的留出集报告，并优先覆盖关键错误、审查否决和 grader 分歧；比例可根据预算扩大。人工结论与模型 grader 不一致时保留两者，复核标准后再汇总。该抽查比例是流程建议，不构成结果可靠性的自动保证。

现有 `eval_groundedness()` 可保留作为“与运行笔记的一致性”辅指标；主指标新增原文 evidence-based evaluator。`raw_notes` 不能继续作为唯一事实真值，因为其中含模型产生的内容。

## 7. 结果怎样计算与解释

费用下降率：`(cost_A - cost_X) / cost_A`。延迟下降率同理。支持率变化用百分点；无支持主张率的相对下降与绝对百分点同时给出，避免小分母夸大效果。

对每个任务做配对比较，并按任务聚类 bootstrap 得到 95% 区间；重复样本、同一报告内主张不作为独立任务计算。小试主要看方向与错误案例，正式结果同时报告均值、中位数、区间和任务层差异。

四组帮助区分：

- `B - A`：无 Reviewer 时，Context 的影响。
- `C - A`：原上下文下，Reviewer 的影响。
- `D - C`：有 Reviewer 时，Context 的影响。
- `(D - C) - (B - A)`：两种改动的交互方向；对质量、成本分别解释。

不把所有指标压成一个不透明综合分。选择时看质量/费用/延迟的折中曲线：D 更准确但更慢应明确写出来，而不是笼统说“性能提升”。

## 8. 建议预先登记的采用门槛

以下是可调整的产品目标，**不是预测或已测结果**：

1. 固定越权测试集未授权读取成功数为 0；关键用户约束保留率为 100%。
2. B 相对 A 的完整性与事实支持率，配对差值的 95% 区间下界不低于 -3 个百分点；费用下降目标为 20%。未证明非劣时不称为质量无损。
3. D 相对 A 的无支持主张率相对下降目标为 20%，同时报告绝对差；完整性满足同样非劣门槛。
4. D 的费用、P95 延迟先以不高于 A 的 1.25 倍作为期望上限。若超过，列出质量收益并决定是否按复杂任务启用；这不是失败后偷偷修改的统计标准。
5. 若 A 的无支持率已接近 0，相对下降指标无意义，改以预先定义的缺陷注入集上的漏检率和误拦率作为审查验收，公开报告指标变更理由。

如区间跨越门槛，结论为证据不足；如 B 更便宜且质量可接受而 D 收益不足，可以只采用 B。最终不预设必须采用全套方案。
